# POVA5 Balanced Hyper

Аудит и проектирование обратимой systemless-кастомизации для TECNO POVA 5 с визуальным языком, вдохновлённым HyperOS.

> **Статус: DESIGN_ONLY.** Проверки устройства в рамках этого коммита не выполнялись. Ни один раздел, загрузчик, системный APK, root-менеджер или параметр безопасности не изменялся.

## Устройство

Данные ниже предоставлены пользователем и **не проверены** в ходе работы с репозиторием:

| Поле | Значение |
| --- | --- |
| Устройство | TECNO POVA 5 |
| Модель | `LH7n-H894LM-U-RU` |
| SoC | `MT6789` |
| ABI | `arm64-v8a` |
| Платформа | Android 14, API 34 |
| Сборка | `250416V782` |

Источник истины для уточнения — [docs/DEVICE_PROFILE.md](docs/DEVICE_PROFILE.md).

## Цель

Определить, какие элементы интерфейса можно безопасно реализовать как **обратимый systemless-слой**, не затрагивая системные разделы и настройки безопасности, и подготовить план проверки с гарантированным откатом.

## Принципы

1. **Только аудит и проектирование.** Реализация, установка и запуск на устройстве — отдельные фазы после явного разрешения.
2. **Никаких изменений устройства.** Запрещены запись в разделы, прошивка, разблокировка загрузчика, замена системных APK, изменение SELinux/Verified Boot и установка системных настроек.
3. **Никаких выдуманных результатов.** Непроверенные сведения помечаются как предоставленные или неизвестные. Файлы отчётов не создаются до реальных проверок.
4. **Обратимость по контракту.** Любой будущий модуль должен отключаться и удаляться без остаточных изменений.
5. **Минимальный след.** В репозиторий не попадают APK, дампы прошивки, ключи, пароли и персональные данные.

## Разделение задач (MECE)

| Клетка | Вопрос | Граница |
| --- | --- | --- |
| **C1** | Что именно у нас за устройство? | Только факты и способ их безопасной проверки |
| **C2** | Как устроен обратимый systemless-модуль? | Механизм, состояние, откат, конфликты |
| **C3** | Что из HyperOS-подобного интерфейса реализуемо? | Пользовательски видимый слой и ограничения API |
| **C4** | Как проверить и восстановить исходное состояние? | Тесты, критерии остановки, runbook восстановления |

Подробные правила непересечения — в [.mece/SYNTHESIS.md](.mece/SYNTHESIS.md).

## Рабочий поток

1. Прочитать профиль устройства и уточнить статус каждого поля.
2. Пройти волны `W0 → W4`, не переходя шлюз без фактических данных.
3. Заполнять только статусные разделы `TASK.md`; фиктивные отчёты не создаются.
4. Перед любой реализацией получить отдельное разрешение на работу с устройством.
