# C1 — Аудит устройства

| Поле | Значение |
| --- | --- |
| ID | `C1-DEVICE-AUDIT` |
| Статус | `NOT_STARTED` |
| Волна | W1 |
| Зависимости | W0 |
| Владелец | Роль аудитора устройства |
| Разрешение на работу с устройством | **НЕ ПОЛУЧЕНО** |

## Цель

Получить минимально достаточный, проверяемый набор фактов об устройстве, необходимый для выбора архитектуры модуля и оценки интерфейса.

## В объём входит

- Подтверждение identity-полей из [docs/DEVICE_PROFILE.md](../../docs/DEVICE_PROFILE.md).
- Определение наличия root-менеджера и поддерживаемого механизма overlay.
- Инвентаризация лаунчера, системных UI-компонентов и локали.
- Уточнение политики обновлений OTA.
- Присвоение статуса достоверности каждому полю.

## В объём не входит

- Выбор механизма модуля (C2).
- Оценка визуальных решений (C3).
- Проверки и откат (C4).
- Любая запись на устройство.

## Входные данные

- Значения, сообщённые пользователем: `LH7n-H894LM-U-RU`, `MT6789`, `arm64-v8a`, Android 14 / API 34, `250416V782`.
- Доступ к `adb` в read-only режиме — при наличии разрешения.
- Физический доступ к устройству — не требуется для текущей фазы.

## Чек-лист действий (только при разрешении)

### Идентичность и платформа

- [ ] Сверить `ro.product.brand`, `ro.product.model`, `ro.product.device`.
- [ ] Сверить `ro.product.cpu.abi` и `ro.product.cpu.abilist`.
- [ ] Сверить `ro.build.version.release`, `ro.build.version.sdk`, `ro.build.display.id`, `ro.build.fingerprint`.
- [ ] Зафиксировать кодовое имя, если оно доступно без записи.
- [ ] Отметить несовпадения с данными пользователя как `DISCREPANCY`, не исправлять молча.

### Возможности системы

- [ ] Проверить доступность `cmd overlay` и перечислить 현재 overlay read-only.
- [ ] Определить, какие пакеты владеют статус-баром, шторкой и lockscreen.
- [ ] Определить лаунчер и поддержку иконок/темы через его пользовательский интерфейс.
- [ ] Уточнить локаль и набор resource-квалификаторов (`values-ru`, плотности).
- [ ] Зафиксировать частоту/источник OTA как наблюдаемый факт или `UNKNOWN`.

### Root и безопасность

- [ ] Обнаружить root-менеджер read-only (без установки и без запуска команд записи).
- [ ] Прочитать props состояния загрузчика/Verified Boot, если доступны.
- [ ] Не делать выводов о разблокировке из пустых значений.
- [ ] Не проверять и не изменять настройки безопасности записью.

## Запрещённые операции

```sh
fastboot flash ...
dd if=... of=...
adb shell su -c 'mount -o rw /system'
adb shell magisk --install-module ...
adb shell pm install ...
adb shell settings put ...
adb shell setprop ...
adb shell setenforce ...
adb pull /system/...
```

## Политика доказательств

- Для каждого `OBSERVED_READ_ONLY` поля указывать: команда, дата, результат с маскированием.
- Пустые ответы остаются `UNKNOWN`.
- Полные `dumpsys`, `logcat`, APK и образы разделов в репозиторий не добавляются.
- `REPORT.md` не создаётся. Результаты идут только в блок «Результаты» ниже.

## Критерии остановки

- Нет разрешения на работу с устройством → оставаться в `NOT_STARTED`.
- Команда требует записи или root-прав вне read-only → пропустить и пометить.
- Обнаружено несоответствие модели/сборки → вернуть вопрос пользователю, не продолжать экстраполяцию.
- Запрошен дамп раздела или системного APK → отказать.
