| Поле | Значение |
| --- | --- |
| ID | `C3-UI-FEASIBILITY` |
| Статус | `BLOCKED` (до G1 и G2) |
| Волна | W3 |
| Зависимости | C1, C2 |
| Владелец | Роль UI/совместимости |
| Разрешение на работу с устройством | **НЕ ПОЛУЧЕНО** |

## Цель

Определить, какие элементы HyperOS-подобного интерфейса достижимы в рамках обратимого systemless-слоя, а какие требуют запрещённых изменений.

## В объём входит

- Формулировка «Balanced» как сдержанного визуального языка.
- Карта элементов UI → механизм → ограничение.
- Анализ RRO/ресурсов Android 14 для target-пакетов из C1.
- Оценка лаунчер-зависимых и пользовательских сценариев.

## В объём не входит

- Реализация тем, APK, иконок и макетов в этом коммите.
- Выбор механизма доставки (C2).
- Тестирование на устройстве (C4).

## Принцип «Balanced Hyper»

Не копирование прошивки, а **сдержанный набор**: палитра, типографика, отступы, радиусы и иконографические акценты. Не использовать логотипы, названия или ассеты HyperOS/MIUI без прав. Формулировка в документах — «HyperOS-inspired», не «HyperOS ROM».

## Ограничения Android 14 / RRO

- Не предполагать доступность `cmd overlay` до данных C1.
- Не предполагать совпадение подписей overlay и target до проверки.
- Не использовать smali-патчи и замену системных APK.
- Не активировать Accessibility/device admin как «движок интерфейса».
- Не менять системные настройки через `settings put`.

## Политика доказательств

- Визуальные решения — `DESIGN_PROPOSAL`, пока не подтверждены C4.
- Гипотезы помечаются `UNKNOWN`, а не `PASS`.
- `REPORT.md` не создаётся. Результаты — только ниже.

## Критерии остановки

- Target-пакет или ресурс не подтверждён → элемент остаётся `UNKNOWN`.
- Требуется замена системного APK → `OUT_OF_SCOPE`.
- Требуется изменить настройку безопасности → `OUT_OF_SCOPE`.
- Требуется добавление APK в репозиторий → запрещено `.gitignore`.
